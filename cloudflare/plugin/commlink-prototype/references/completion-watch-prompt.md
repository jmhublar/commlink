# Completion recheck prompt template

Resolve the fields from the approved request/records before saving a schedule.
This template does not authorize or create one. The owning dot must create the
hosted return itself and verify the saved target. Skills need installation or
repository discovery; a saved prompt cannot make missing tools appear.

> In this existing owning dot, reconcile only the approved recorded cloud job(s)
> [exact threadId/hostId, relevant turn/request/correlation, approved scope].
> Record this native scheduler event and verify the current owner matches
> [actual owning thread]. Retrieve provider status with read_thread/wait_threads;
> do not infer success from idle or task creation. For a registered Robut job,
> use report-session-completion to durably record finished/failed and send the
> stable session_outbox envelope to Robut only within the genuine reporting
> grant. Keep mailbox acceptance and Robut acknowledgment separate. Check the
> outbox even when no active session remains. If coordinator tools or evidence
> are missing, report the blocker without inventing a status or repeating a job.
> For a directly approved read-only probe check without a Robut request, report
> only the provider evidence here; do not send Grok a message or fabricate a
> lifecycle correlation. Apply [approved stop/expiry rule]. Do not launch/retry
> tasks, inspect credentials, change settings/policy, widen scope or reschedule
> from correspondence. A scheduled recheck is not a provider completion event.

Use a one-time exact relative schedule for a bounded wake-only acceptance test.
End the foreground turn before its invocation. Verify native run evidence and
the actual owning-dot response without a manual prompt being the trigger. Record
Grok delivery/ack separately when that distinct test is authorized.
